# Changelog

All notable changes are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/). From `v1.0.0` on, entries are
generated by `cz bump` from Conventional Commits.

## [Unreleased]

### Added

- The orchestrator chooses message intents (what to ask, tone, a
  verified mention of an earlier message) instead of copying reviewed
  text; code composes every message (ADR-0018).
- The model can hold an action for human review; held actions are never
  dispatched until `followup review --approve` (or `--reject`), with an
  audit event and a held-backlog alert.
- A PostgreSQL ledger shares the daily LLM budget across all workers
  and fails closed (migration `0008`).
- `make db-init` prepares a local PostgreSQL with a service role.
- `docs/security/owasp-llm-top10.md` maps every OWASP LLM risk to its
  controls and `@pytest.mark.owasp_llm` tests, checked by a meta test.

### Changed

- `followup run` without a database accepts only `--dry-run`; a second
  process could otherwise re-enqueue work the first one sent.
- One 60 s deadline bounds a whole plan; each model call keeps 20 s.
- The model's rationale is stored as a non-authoritative audit note and
  rejected when it copies the note.
- In stub mode the note interpreter makes no call, so the demo no longer
  logs validation warnings.

### Fixed

- PR #19's source-state dedupe suppressed time-driven escalation of an
  unchanged overdue task; the slot now carries an escalation stage.

- Alerts and the dashboard referenced fourteen metric families that no
  code emitted. The catalogue in `docs/14` is now implemented
  (`infrastructure/telemetry.py`), exported by the API and by CLI
  commands (`FOLLOWUP_METRICS_FILE`), and checked against the code.
- Orchestrator free text could carry invented deadlines, names, claims
  and obfuscated contacts; `domain/free_text.py` rejects them.
- Task titles and project names are screened for injection; a flag
  withholds every untrusted field from the model.
- A task whose project name needed cleanup was dropped; it is now
  followed up without project authority (`noncanonical_project` flag).
- 500/502/504 on a delivery write mean "unknown" and are reconciled
  before any resend.
- Logs keep LLM purpose, model and cost, orchestrator stages, error
  classes, and run and plan summaries; `exception` logs at error level.
- `make test-fast` no longer collects image and benchmark tests; the
  orchestrator's history tool reads the newest actions; build warnings,
  `.dockerignore` gaps and the unpinned PostgreSQL image are fixed.

### Added

- Bounded LLM orchestrator (ADR-0016): for every new actionable task
  state the model plans the action with read-only tools (`get_history`,
  `check_plan`, `submit_plan`) inside a policy-computed envelope; a
  deterministic guard approves the plan, code renders all facts, the
  dedupe slot stays with the policy baseline, and every plan is audited.
  Offline model for the demo and tests; Hypothesis containment property.
- Migration `0005`: task index for the orchestrator's history lookup.

### Changed

- Planning runs concurrently within a batch; plan traces are written in
  the decision's transaction. Benchmarks re-measured.
- Documentation consolidated: process reviews removed, API and
  deployment guide (`docs/19`), scope and status (`docs/08`), README.

- Final integration: bounded parallel writes, private metrics listener and
  bounded OTLP export, source-project provenance, shared PostgreSQL request
  windows, durable recipient/day quotas, isolated ZAP target, and a manual
  GHCR publication/attestation workflow. All new execution gates are pending.
- Authenticated API core: Ed25519 service tokens, explicit route
  capabilities, project-authorized reads, bounded request admission and
  a separate metrics application. Deployment wiring remains outstanding.
- Offline LLM evaluation: minimal and expanded versioned
  datasets, source-bound scripted replay, independent benign-quality and
  structural-safety gates, and Hypothesis properties. Committed responses
  are synthetic; live-provider quality remains unverified.
- Operations levers: `followup maintenance prune` with retention
  per data class (`config/retention.toml`) and the maintenance database
  role (migration `0003`); `make db-backup` / `make db-restore` with a
  round-trip test; runbook commands checked against the CLI.
- Completion of the image work: the runtime image runs the `followup` CLI (end-to-end
  image test with PostgreSQL 18 and the mock), CI smoke job comparing a
  fresh demo with `samples/`, and the 10,000-task benchmark
  (`make bench`, `docs/benchmarks.md`).
- Security evidence (partial): least-privilege database role
  `followup_app` (migration `0002`, append-only audit trail) with
  integration tests; generated ASVS traceability report with a
  consistency gate; meta tests that pin the security gates; gitleaks
  over the full history; CycloneDX SBOMs; Docker Security and LLM
  Prompt Injection checklists.
- Hardening (partial): multi-stage Dockerfile (`runtime`, `mock`)
  pinned by digest, hadolint, Trivy config and image scans, container
  image tests, Schemathesis against the mock OpenAPI, mutation testing
  of the decision core with a 90 % gate in a nightly workflow.
- Observability stack: Prometheus alert rules with promtool
  tests and runbook links, Grafana provisioned as code, Loki, Alloy OTLP
  pipeline with attribute redaction, `make obs-check` and `make obs-smoke`.
- Full quality gate set: Semgrep project invariants with tests,
  xenon, vulture, deptry, pip-audit, codespell, yamllint, zizmor,
  check-jsonschema, validate-pyproject, commitizen, MkDocs strict build,
  Dependabot, CODEOWNERS, pull request and issue templates.
- Tooling, mock receiver and persistence.
- Domain core with rules R1–R9.
- OpenAI model router for the GPT Sol generation (partial).

### Changed

- `PgRepository.record_decision` makes five round trips instead of
  eight: the foreign key proves the run exists, decisions without an
  action skip the outcome update, and a fresh insert is returned without
  reading it back (10,000 tasks: 294 s → 83 s).

### Fixed

- Retention preserves duplicate identity independently of message payloads,
  ages terminal actions from actual completion, and retains unfinished or
  recently finished runs. Decision/audit writes use one fewer round trip;
  stable source positions preserve report order under concurrent commits.
- API admission now precedes body parsing, repository reads apply project
  authority before response limits, and configured logging preserves
  sanitized security events. Undeclared public routes fail closed.
- Container configuration and fixtures remain readable by the non-root
  runtime under restrictive host permissions; secret scans verify worktree
  Git metadata before scanning.
- The runbook named two commands that do not exist
  (`followup actions requeue`, `followup report --task`); it now
  describes the existing levers, and a meta test keeps it that way.
- The draft validator no longer lets a placeholder hide a host or a
  mailbox (`{project}.com`, `{recipient_name}@example.org`).
- The mock receiver's OpenAPI now documents the error responses it
  actually sends (400, 404, 409, 413, 422, 503 and injected faults).
- PostgreSQL tests without a reachable Docker daemon now fail in CI (or
  skip locally) with the daemon address and reason, instead of an
  unrelated unraisable-socket error from the Docker SDK at shutdown.
